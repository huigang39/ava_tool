# AvA Tool

AvA Tool 是一个面向嵌入式调试和电机控制实验的实时变量监控工具。它可以从 ELF/AXF 符号、手动地址、J-Link、UDP、SHM 或 CSV 数据源读取变量，并在 Monitor/Scope 中进行表格、时域曲线、FFT 频域分析、波形注入和 Bode 扫频观察。

## 主要功能

- 变量管理：拖入 ELF/AXF/BIN/CSV 文件，浏览符号并添加变量；LOCAL 标量可绑定动态库中的 C 读写函数。
- 设备管理：创建设备类型及其实例，把动态库中的 C 函数绑定为实例方法或发现方法，并将输入、输出或返回值映射到类型化属性。
- 实时监控：按 Monitor 和 Scope 组织通道，支持表格视图和曲线视图。
- J-Link 采样与 RTT：支持普通轮询、HSS 高速采样，以及复用当前调试连接的 SEGGER RTT 双向终端。
- 日志复制：RTT、SWO/ITM、SDK 调用日志与历史、序列执行、电机操作记录、示波器操作、Flash 擦除和仿真求解日志支持鼠标选中后 `Ctrl+C`、`Ctrl+A` 全选，以及“复制全部”。
- FFT 分析：Scope 可切换到频域视图，FFT 在后台线程计算，避免阻塞界面 FPS。
- 波形发生器：对可写变量配置正弦、方波、三角波输出。
- Bode Plot：选择写入、输入、输出通道后执行扫频并绘制幅频/相频曲线。
- CSV 导入导出：可导入历史数据，也可导出当前 Monitor 的采样结果。
- 会话保存：保存 Monitor、Scope、变量、布局和最近打开记录。启动时会弹出最近 AVA 会话选择窗口，不会自动载入上一次会话；双击 `.ava` 或通过命令行指定文件时直接打开指定会话。
- 应用更新：从配置的更新地址读取安装包，可下拉选择版本安装，默认选中最新版本。

## 快速开始

1. 启动 `ava_tool`。
2. 在顶部栏选择 J-Link 设备，设置 SWD 速度，然后点击 `CONNECT`。
   连接后在“设备”菜单点击 `RESET MCU` 复位目标；复位不再绑定容易误触的全局快捷键。
3. 将 ELF/AXF 文件拖入 Variables 窗口，或点击 `Load File...` 加载。
4. 在符号列表中把变量拖到 Monitor 的 Scope 里。
5. 在 Scope 中查看实时曲线；点击 `Freq` 切换 FFT 频域视图，点击 `Time` 回到时域。
6. 点击 `Export CSV`，选择导出当前 Monitor 全部数据、某个 Scope 或单个通道。

## 界面说明

### 顶部栏

- `File`：新建、打开、保存会话，以及最近会话。
- `Tools`：计算器、Bode Plot、Assembly Viewer 等工具入口。
- `工具 → 功能安全`:选择自己的配置目录和 JSON,从已加载 AXF/ELF 展开安全对象,也可指定其它子系统路径.程序不内置诊断 JSON.故障位,枚举,函数返回值与普通数值分别解释,计数非零不会被统一判为故障;支持单值解析,报告和会话恢复,详见 [使用与配置](docs/safety.md).
- `Help`：版本信息和更新检查。
- J-Link 区域：选择设备、设置速度、连接/断开、复位 MCU，并可打开 RTT 终端。
  设备与 AXF 的匹配状态、详细原因和构建标识显示在连接/断开按钮的悬浮提示中。
- 顶栏 `PAUSE`：全局暂停显示刷新；采集线程仍会继续工作。

Dock 面板上下或左右停靠时，在标签栏右侧空白处，上下停靠时双击左键、左右停靠时双击右键可折叠当前面板组，把空间让给相邻面板；再次用同一按键双击该空白处恢复原来的分配比例。标签页和关闭按钮不会触发折叠，窄面板也保留一小段空白供双击展开。上下排列折叠为标题栏，左右排列折叠为窄条；标签、变量和采样保持不变。折叠状态及展开比例随布局和会话保存。Monitor 和变量管理器的标签页悬浮时按 `F2` 可重命名；浮动窗口仍可双击标题栏重命名。

SDK 数据表的 `=` 手柄可将整表或单个字段拖入变量管理器/监视器，随后自动持续读取，在变量管理器或监视器里改值会自动下发。移除最后一个绑定变量后停止自动同步，频率仍可在表头调整。表格不再提供“更新”勾选列或自动读取/自动写入开关，类型统一显示为 `u32`、`i32`、`f32`、`f64` 等短名称。

### DSOX2024A 示波器

在「SDK 调用器 → C/C++」中点击 **DSOX2024A** 快捷入口，即可在调用器内显示示波器界面；也可切换到「SDK 函数调用」。
左侧复用变量监视器显示 CH1–CH4 波形，右侧为仪器控制。

- USB/VISA：资源字符串留空自动查找 DSOX2024A，也可填写指定设备的 VISA Resource String；Windows 需安装 64 位 VISA。
- LAN/TCP：填写示波器地址，默认端口 5025。通信在后台执行，连接后读取现有设置。
- 支持运行、停止、单次触发、指定通道采集、自动设置、复位；通道开关、量程、偏置、耦合、探头倍率；时基、时间偏移、边沿触发；频率、Vpp、RMS 测量及文本 SCPI 指令。
- 选择读取通道、点数，点击「读取波形」或开启「自动刷新波形」。一次读取替换上一帧，保留波形标定电压、触发前负时间及实际采样间隔。运行时多通道依次读取；比较同次采集请先停止仪器。
- 波形沿用监视器的缩放、悬停读数、两点时间测量、FFT、CSV 导出；点数计入顶栏总数。CSV 保留短时间间隔精度。
- 关闭调用器或退出示波器界面会断开连接（多个调用器共享同一示波器连接）；会话保存连接参数，重新打开不自动连接或下发设置。USB 功能依赖 VISA 运行库，LAN 功能取决于仪器网口配置。

开发验证：`python tests/run_sim_sampler_test.py --dso`，使用本机回环 SCPI 模拟仪器，覆盖后台通信、四通道波形、仪器错误与超时、窗口关闭及会话恢复，不访问硬件。

### JFlash / J-Link 烧录与数组读取

在“工具 → JFlash / J-Link 烧录器”中，原有固件下载、烧录和校验保留在“固件烧录”分页。

“读取 Flash / 数组”分页可填写十六进制起始地址与字节长度（单次最多 16 MiB），通过 J-Link 读取原始数据，支持取消。读取不擦除、烧写或复位目标。

- 支持 float16、float32、float64，以及有符号/无符号 8、16、32、64 位整数，可选择大小端。
- 选择新的类型、字节序或横轴间隔后点击“重新解析”，直接使用已读取的原始字节。
- 拖动“将数组拖到变量管理器或监视器 Scope”到已有 Scope，可绘制静态数组；横轴默认是索引，也可设置为采样间隔。曲线使用双精度，整数预览保留原值。
- 原始数据可保存为 BIN，也可打开 BIN 离线解析和绘图。读取参数随 `.ava` 保存；拖入变量管理器的数组以单个可折叠节点展示，展开后按索引查看数值和地址，也可继续拖到 Scope。变量管理器中的数组原始字节和折叠状态随 `.ava`、`.var` 保存；读取窗口中的快照可通过 BIN 保留。

### 变量重写与参数配置


参数列表编辑器支持三个独立来源：机械配置（mech）、硬件配置（板子）、软件配置（software）。打开一个完整参数 JSON 后，在对应行选择型号，或用该行的打开按钮选取文件；仅替换对应分组，保留其他两组的修改。变量重写窗口的“分组配置…”进入同一编辑器。

参数配置中，读取值与写入值不一致时以红色高亮；读取值与默认参数不一致时以黄色高亮。两者同时不一致时红色优先。字段行、写入控件、读取值和折叠分组同步标记；写入后回读一致但仍偏离默认参数时，会由红色变为黄色。数值按字段类型比较，等价的数字格式、布尔值和枚举名称不误标；未读取、已失效的读取结果和派生字段不参与比较，没有默认值基准的字段不标黄。

例如选择机械 `NEO_45H`、硬件 `NEO_65H`、软件 `NEO_45H`，配置名称自动为 `NEO_45H/NEO_65H/NEO_45H`，并在应用时写入 `g_foc.cfg.name`。首次组合需另存新文件；应用到设备仍先预览，再手动写入。

组合 JSON 保留完整参数列表，并以 `components.mechanical`、`components.hardware`、`components.software` 保存三个来源名称。旧整机文件仍可打开，组合后按“机械/硬件/软件”顺序命名；设备读回的三段名称也可继续作为组合基础。组合名称最多 63 个 UTF-8 字节，各来源名称不含 `/`，与 MCU 现有名称存储兼容。

某组参数偏离所选预设时，该组名称自动追加 `*`，例如 `NEO_45H*/NEO_65H/NEO_45H`；恢复默认值后自动去掉。多个分组分别标记。此标记与文件是否保存无关，保存后仍保留。配置字段的可选 `preset_value` 随 JSON 保存默认值基准，重新打开后仍可正确识别恢复默认；派生字段、说明等元数据不参与比较。带星号的名称也用于设备配置名称，总长度仍限制为 63 个 UTF-8 字节。

FOC 参数在线编辑可使用固件中的只读 `g_foc_param_info` 核对参数布局、配置地址和状态地址。提供描述区时, AXF、设备和参数 manifest 必须一致, 配置写入仍要求 FOC 处于 DISABLE/FAULT。没有参数描述区的旧固件保留普通变量编辑能力。固件的 `g_foc.cfg` 是待提交配置, 保存并复位后应用。

变量管理器中的顶层变量、结构体/联合体成员、数组元素、位域和手工添加的变量均提供右键“重写变量”入口。点击后自动读取当前值，修改字段并点击“写入改动”；无改动时不会重复写入。

- J-Link 变量按实际类型编辑，写入后回读校验；位域保留相邻位，未改字段保留目标当前值。目标重连/复位或所编辑字段发生并发变化时，需先重新读取。
- LOCAL 标量和手工结构体可直接编辑；LOCAL 标量保留绑定写函数的调用。导入的 Flash/数组快照仅修改本地副本，不会烧写设备 Flash。
- UDP、音频与 SHM FIFO 没有通用的按地址读写/校验接口；仍可打开入口查看具体原因，不会误当成目标内存写入。
- 默认展开当前对象；支持按完整字段路径搜索、“只看改动”、展开/折叠、恢复原值。大数组按页展示。
- 可保存/载入 JSON 预设；严格校验字段路径、类型、枚举选项和数值范围。无效配置整体拒绝，保留当前预览。单次编辑上限为 1 MiB。
- `g_foc.cfg` 及其子字段保持 DISABLE/FAULT 写入检查。完整 `foc_cfg` 仍支持内置执行器预设；配置持久化由固件处理。

重写窗口可直接“刷新当前值（保留改动）”：读取最新快照，保留未冲突的编辑；若同一字段在 MCU 上也被修改，则保留当前预览并提示冲突。需要清空编辑时，使用“放弃改动并重新读取”。界面分别显示 J-Link 断连、MCU 复位/连接变化和 AXF 布局变化；已经连接但快照失效时只需刷新，无需反复重连。AXF 或参数 schema 变化后，可先“备份预览 CSV”保留可识别字段的编辑值，再重新打开变量。JSON 切换共用一次字段布局校验，预设、名称和参数树按需刷新缓存；修改或新增预设文件会在下次读取/导入时更新缓存。

### 远程文件与烧录配置

在 `Settings → Remote Files / 设置 → 远程文件` 配置固件地址、会话文件地址和更新地址。烧录器与变量管理器共用固件地址。目录地址使用服务器的浏览页（例如 `http://host:8080/files/Firmware`）；AXF/ELF 和 AVA 也支持直接下载 URL。本机文件共享无需账号密码；旧服务器需要认证时，可展开“登录设置（可选）”填写共用的用户名、密码。

`Help → Check for Updates / 帮助 → 检查更新` 默认从 `https://github.com/huigang39/ava_tool/releases` 获取正式发布的安装包，也支持自定义更新目录。使用当前填写的更新地址，列出其中的 `ava_tool_setup_<版本号>.exe` 安装包。版本下拉框按版本号从新到旧排序，默认选中最新版本；也可选择旧版或当前版本，点击“下载并安装”，下载完成后确认重启安装。手动检查允许降级和重装，自动检查仅在发现新版本时提醒。回归验证：`python tests/run_sim_sampler_test.py --update-versions`。

- 配置会保存为软件默认设置，并在保存 `.ava` 时写入 `remoteFiles`。账号密码包含在配置中；旧会话没有该字段时沿用软件设置。
- 烧录器的固件路径、BIN 基地址、全片擦除和复位选项随 `.ava` 的 `flashTool` 保存、恢复。
- `File → Recent Sessions / 文件 → 最近会话` 会列出会话文件地址里的远程会话，可刷新并直接打开；已打开的远程 URL 也会进入最近记录。
- 变量管理器点击 `Remote AXF/ELF / 远程 AXF/ELF` 选择服务器文件，也可重新加载当前远程文件。下载、解析在后台执行，保存会话时保留源 URL。
- 远程 `.ava` 中相对的 ELF/AXF 路径按会话的远程 URL 解析。保存远程会话会提示选择本地 `.ava` 副本。
- 远程目录支持 HTML 文件链接，认证沿用固件服务器的 `POST /login` 与会话 Cookie。

“设置 → 远程文件”下方的“本机文件服务器”可直接共享本机文件夹（Windows）：首次运行自动创建 `.ava_tool/shared`，并创建 `Firmware`（固件）、`Sessions`（会话）、`Updates`（更新包）子目录，默认端口为 `8090`。无需手填目录，点击“打开共享文件夹”放入文件，再点击“启动服务器”即可。已有自定义目录会保留，需要调整时使用“更换目录”。选择本机 Wi-Fi / 局域网 IP 后可复制 HTTP 地址。同一 Wi-Fi、手机热点或局域网内的设备可以用浏览器访问目录并下载文件；允许 AvA Tool 通过 Windows 防火墙的专用网络后即可访问。`127.0.0.1` 仅供本机使用，服务器随 AvA Tool 退出而停止，也可勾选“启动程序时开启服务器”。

固件、会话和更新包子目录均相对于共享根目录，留空使用根目录。例如共享 `D:/Share`，子目录分别填写 `Firmware`、`Sessions`、`Updates`；放入 AXF/ELF、AVA 和 `ava_tool_setup_*.exe` 后，点击“将共享地址填入远程文件”，会一次替换上方三个地址并清空账号密码。其他设备的 AvA Tool 可填写相同 HTTP 地址，沿用远程会话、符号加载及检查更新功能。共享文件夹和自动启动选项只保存到本机 `.ava_tool/local_file_server.json`，不随会话迁移；远程地址仍按原有方式保存到软件默认设置与 AVA 会话。已有 AVA 内的符号路径应为共享范围内的相对路径或该服务器的 HTTP 地址。

服务器仅提供目录浏览、GET/HEAD 下载，不允许上传或修改文件，也不提供共享根目录之外的文件。中文名称和大文件使用 URL 编码及流式下载。回归验证：`python tests/run_sim_sampler_test.py --local-file-server`，覆盖现有远程客户端、更新器、中文及二进制文件、并发访问、配置恢复、目录边界及停止/重启。

同一页面的“局域网服务器 → 扫描局域网服务器”会在后台发现开启共享的新版 AvA Tool，包括使用不同 HTTP 端口的服务器。结果显示服务器名称、IP、端口及软件版本；选择一项后可预览其固件、会话、更新目录，点击“使用此服务器”才会替换三个远程地址。只扫描不会改变当前配置，未发现结果时仍可手动填写地址。共享端可设置“服务器名称”（留空用电脑名称），修改名称或有效的子目录会立即更新发现信息。重新扫描会移除已停止的服务器；结果按服务器实例去重，优先显示局域网 IP。

自动发现使用 IPv4 UDP `45990` 与局域网组播 `239.255.42.99`（TTL 1），扫描约两秒，本机无需开启共享也可扫描。双方需允许 AvA Tool 的专用网络访问；Wi-Fi 的客户端隔离或禁用组播可能影响发现，此时可手动填入已知 HTTP 地址。回归测试另覆盖多个服务器、自定义端口、中文名称、目录映射、重复响应去重、名称刷新及停止服务器后的重新扫描。

Windows 点击窗口 X（或 Alt+F4）默认弹出“退出程序 / 缩小到托盘 / 取消”选择框，可勾选“记住我的选择，设为默认行为”，以后按所选默认行为执行；在“设置 → 窗口关闭行为”可随时改为“每次询问”“退出程序”或“缩小到托盘”。选择退出后沿用原有的未保存会话提示，选择托盘则保留后台文件共享与局域网发现。最小化按钮保持普通窗口最小化，也可使用“文件 → 最小化到系统托盘”。托盘图标可恢复窗口，右键“退出程序”与“文件 → 退出”直接进入真正退出流程。选项保存在本机 `.ava_tool/window_preferences.json`；旧版设置升级后，关闭按钮默认恢复为询问。托盘创建失败时保留选择框供重试或退出。回归：`python tests/run_sim_sampler_test.py --system-tray`。

本地编译打包执行 `python scripts/release.py`；可加版本号更新版本。脚本不执行 Git 提交、推送或 GitHub 发布。运行中程序占用默认输出文件时，可以用 `make package BIN_DIR=build/local-package/bin` 生成同一安装包。维护脚本统一在 `scripts/`，用途与运行方式见 [脚本目录](scripts/README.md)。

### Variables

- `Load File...`：加载 ELF/AXF/BIN。
- `Add Variable`：手动添加变量，可选择 JLINK、LOCAL、SHM 或 AUDIO 数据源。旧会话中的 MANUAL 变量会自动迁移为只读 LOCAL 变量。
- 属性编辑器会保留当前标量、STRUCT 或 UNION 类型；DWARF 联合体会按 UNION 展示和展开，LOCAL 也可手动创建联合体。
- `Refresh(ms)`：变量窗口后台轮询刷新周期。
- `Function Browser`：与“符号文件”悬浮面板堆叠在变量表下方，可独立展开；符号文件面板同时提供 ELF/AXF/BIN 加载、远程文件和符号浏览，并支持按名称或地址检索。双击符号树或搜索结果中的变量可直接加入变量管理器。固定后的悬浮窗可拖动标题移动，并可拖拽边框调整尺寸。支持同时加载多组动态库及声明导出函数的 C/C++ 头文件，每个函数和变量绑定都会记录所属动态库。也可以把 DLL/SO/dylib 和头文件直接拖入变量窗口；右键点击 LOCAL 标量后选择 `Bind Read/Write Functions...` 绑定访问器。C++ 类和成员方法可浏览，但变量访问器必须绑定顶层 C ABI 函数。
- 读取访问器支持 `T read(void)` 或 `status read(T *out)`；写入访问器支持 `status write(T value)` 或 `status write(T *value)`。`status` 可以是 `void` 或整数，负整数表示调用失败。函数在独立工作线程中按 `Refresh(ms)` 周期调用。
- 从符号表或变量表拖拽条目到 Monitor Scope，可创建监控通道。
- 双击结构体、联合体或数组名称可临时聚焦该子树，单击左侧箭头展开或折叠。顶部路径可点击返回任意上层，也可用“返回上级”“全部变量”退出；长路径自动换行。聚焦保留实时刷新、成员操作、完整字段路径和原有展开状态。聚焦是临时浏览状态，成功重载符号或加载会话后回到全部变量。

### Monitor 和 Scope

- `Add Scope`：新增 Scope。
- `Clear Data`：清空采样数据并重启采样状态。
- `Export CSV`：选择导出全部 Scope、某个 Scope 或单个通道；包含隐藏曲线的原始数据，保留 Scope/通道名称和时间戳。
- `框选丢弃`：在 Monitor 顶部开启后，在需要处理的 Scope 时域图中用左键向左或向右拖拽选择时间段，预览范围和点数后点击“丢弃选中区间”；点击“取消”或按 Esc 退出。丢弃范围包含当前 Scope 的全部通道（含隐藏曲线），其他 Scope 不受影响；保留原时间戳，统计和 CSV 导出同步更新。暂停显示或采样时也可使用；Flash 数组快照暂不支持。
- `History(s)`：保留并显示的历史时长。
- `Max Pts`：单帧绘图点数预算。
- `MaxHz`：目标采样率。
- `HSS/POLL`：切换高速采样或普通轮询。
- `FULL/FOLLOW/MANUAL`：切换绘图视图模式。

Scope 工具栏：

- `Plot/Table`：切换曲线视图和表格视图。
- `Freq/Time`：切换 FFT 频域视图和时域视图。
- `Table`：显示或隐藏右侧 Stats/Peaks 面板。统计区默认“横向”，同一行并排对比各通道的当前值、最小值、最大值、峰峰值、平均值、有效值和 N；表头和指标列固定，通道较多时可横向滚动。顶部下拉框可切换为“纵向”，每个通道单独列出全部指标。每个 Scope 的选择随会话保存。曲线区域固定，右侧统计/峰值内容独立滚动；变量表格视图仍可上下滚动。
- `Hide line/Show line`：隐藏或显示当前 Scope 内所有曲线。
- `Hide Scope/Show Scope`：折叠或展开当前 Scope。
- `Pause/Resume`：暂停或恢复当前 Scope 的采集任务。
- TABLE 视图中右键通道可通过 `Access mode / 读写模式` 切换只读或读写；该操作会应用到当前选择的通道并随会话保存。JLINK、SHM 和 LOCAL 支持读写，LOCAL 写入会调用变量绑定的写函数；AUDIO 保持只读。
- TABLE 视图与变量管理器使用相同的聚焦交互：双击分组名称进入子树，单击箭头展开或折叠，顶部路径、“返回上级”和“全部变量”用于返回。聚焦仅改变表格显示范围，保持原有通道、采样、数值编辑和展开状态。
- 变量管理器与 Monitor TABLE 的右键菜单共享删除、属性编辑、读写模式、DWT 跟踪和枚举编辑功能；LOCAL 通道也可从 Monitor 直接打开所属变量的函数绑定窗口。
- 各类变量的右键菜单保持固定布局；当前变量不支持的操作会置灰而不是隐藏。ENUM 的类型列会显示底层整数类型，例如 `ENUM (u8)`、`ENUM (i8)` 或 `ENUM (u32)`。
- 置灰菜单会注明适用条件（如“仅 LOCAL 标量”）；顶层及嵌套变量都可在属性窗口覆盖标量类型，嵌套聚合类型可改成标量并通过“重置”恢复 DWARF 原始类型。
- 每个 Scope 的 TABLE 列宽、表头升降序或手动拖拽顺序都会随会话保存并在下次加载时恢复。

### SEGGER RTT 终端

1. 先在顶部栏连接 J-Link 和目标 MCU，再点击 `RTT`。RTT 终端是可拖动、可缩放的普通工具窗口，不会像弹出菜单一样始终压在其他窗口前面；点击标题栏关闭按钮只隐藏窗口，不会停止已经运行的 RTT。
2. 默认使用 Up Channel 0 接收目标输出、Down Channel 0 向目标发送数据；这两个编号是 RTT 缓冲区通道，不是 RTT Viewer 的虚拟 Terminal 编号。
3. `Control Block` 留空时由 J-Link 自动搜索 `_SEGGER_RTT` 控制块；自动搜索失败时，可填写控制块的固定地址，例如 `0x20000000`，然后重新启动 RTT。
4. 点击 `START` 后，状态会先显示正在搜索控制块，找到后切换为运行状态。发送区支持把换行符附加到输入末尾；下行 FIFO 暂时写满时，未发送完的数据会保留并继续重试。
5. 目标固件需要集成并初始化 SEGGER RTT。若持续找不到控制块，请确认选择了准确的目标器件，并检查控制块是否位于 J-Link 可访问的 RAM 中。

本次运行中成功启动 RTT 后，断开 J-Link 再连接会自动恢复 RTT。点击“停止 RTT”可取消自动恢复，断开期间也可停止。重连保留已有接收日志，清除未发送的旧命令。

接收日志支持鼠标选中后按 `Ctrl+C` 复制，也可按 `Ctrl+A` 全选，或点击“复制全部”直接复制当前全部日志。选中文本或向上滚动查看历史时暂停自动滚动，取消选择并回到底部后继续跟随新输出。

RTT 与内存采样、HSS 共享同一条 J-Link 连接；高采样率下若终端输出延迟，可适当降低 `MaxHz`。关闭或断开 J-Link 时，RTT 读取线程会先停止，不会另行占用 COM 口。

## FFT 使用说明

在 Scope 中点击 `Freq` 进入频域视图：

- FFT 点数可选择 256 到 1048576。
- Peaks 输入框用于设置峰值列表数量。
- `Line/Bar` 可切换频谱绘制方式。
- 频谱计算由独立 FFT worker 线程执行，渲染线程只绘制最近一次计算结果。
- 大点数 FFT 会自动降低计算刷新率，并把用于绘图的频谱压缩到有限点数；峰值检测仍基于完整 FFT 结果。

## 设备管理器

1. 打开 `Tools -> Device Manager`，先创建设备类型，再在该类型下手动添加一个或多个具体设备。
2. 为设备类型选择动态库（Windows DLL、Linux SO 或 macOS dylib）以及声明导出函数的 C/C++ 头文件，然后点击 `Load`。动态库路径、头文件、属性定义和方法绑定都属于设备类型；每个具体设备保存各自的属性实际值。恢复会话或导入类型时不会自动读取头文件或加载动态库，需要手动执行 `Reparse` 和 `Load`。
3. 在设备类型的 `Properties` 中定义 `bool`、定宽整数、`float` 或 `double` 属性。`Discovery Key` 是发现 JSON 使用的稳定字段名，不会随显示名称改变，并且在同一类型中必须唯一。实例方法可以把普通参数绑定到常量或属性值，把指针参数绑定到兼容属性地址，并把输出参数或返回值更新到当前设备实例。
4. 需要批量发现设备时，把类型方法设为发现方法，并配置调用方提供的 JSON 缓冲区 ABI：指定一个可写 `char *` 缓冲区参数、一个 32/64 位整数容量参数和缓冲区大小，例如 `int32_t discover(char *out_json, uint32_t capacity)`。发现函数把 NUL 结尾的 UTF-8 JSON 写入缓冲区；负返回值表示失败。JSON 支持直接返回设备数组，或返回如下对象：

   ```json
   {
     "devices": [
       {
         "key": "stable-device-key",
         "name": "Device 1",
         "properties": { "serial": "12345678", "channel": "1" }
       }
     ]
   }
   ```

   函数返回值必须等于 JSON 中的设备数量；管理器按 `key` 批量新增或更新设备实例，避免重复创建。`properties` 的字段名对应属性的 `Discovery Key`；I64/U64 值必须写成 JSON 字符串，避免 64 位精度损失。同样可以使用 `[{"key":"...","name":"...","properties":{...}}]` 作为顶层数组。现有厂商接口如果返回“数量 + 结构体数组”，需要增加一个薄 C wrapper，把结果转换到上述 JSON 缓冲区 ABI。
5. 保存 `.ava` 会话会保留所有设备类型、实例及其属性值；`.avadev` 导入和导出同样以一个设备类型及其全部实例为单位。

设备方法按 C ABI 调用。建议动态库导出 `extern "C"` 函数，并使用定宽标量或标量指针；当前不支持 C++ 成员函数、可变参数和按值传递的结构体。传给函数的属性地址、字符串和发现缓冲区仅在本次同步调用期间有效，动态库不能保存这些指针或在返回后异步访问。

## 常见问题

### FFT 开启后界面仍然卡顿

优先减少可见通道数量，或缩小可见时间窗口。大点数 FFT 已做后台计算、自动节流和绘图降采样，但 1048576 点 FFT 仍会消耗明显 CPU。

### J-Link 连接失败

检查目标板供电、SWD 线序、设备型号选择和 J-Link 驱动。必要时断开重连 J-Link，或降低 SWD 速度。

### HSS 模式启动失败

降低 `MaxHz` 或减少通道数量。HSS 可达到更高频率，但受 J-Link 型号、目标内存块数量和 USB 带宽限制。

HSS 启动失败后至少等待 200 ms 再重试. 重复或倒退的帧时间戳会触发丢弃异常帧及重新启动, 32 位时间戳正常回绕仍可连续采样. 不根据数值是否为 0 过滤采样点. 当数据从非零跳到 0 时, `.ava_tool/log/ops` 中的 `[HSS-ZERO]` 会记录地址, 类型, 原始字节及时间戳, 每秒最多记录一次; `[HSS-INVALID-FRAME]` 表示帧时间戳异常. 这些记录用于区分原始采样与显示问题, 单条跳零记录不代表设备故障.

### 修改变量值没有生效

确认变量来自可写端口，地址正确，并且输入后按 Enter 提交。

### JSON 参数模板

变量管理器新增“JSON 参数”入口，支持打开、拖入 JSON、目录列表选择、搜索、编辑、保存和另存为。离线查看和编辑不需要连接设备，也不需要 AXF；默认模板及另存文件名为 param_list.json。整数枚举显示下拉框，布尔值显示复选框，类型列在最后。

离线保存保留来源、备注及其他元数据；未保存时切换文件会提示先保存或恢复。需要写 MCU 时，连接设备并加载匹配 AXF，再点击“应用到设备”进入原值/修改值预览，最后点击“写入改动”。在线配置页列顺序为“字段 / 原值 / 修改值 / 类型”，原值和类型使用正常文字颜色。

JSON 使用 foc-parameters version 1，包含 target 和 parameters 列表；每项的 path、type、value 必填，可选 enum、unit、min、max、description。路径相对于目标变量，不存储地址。整数类型也可用 enum 定义名称到整数的映射，在编辑器中使用下拉框。推荐数值用十进制字符串，避免 64 位整数精度损失。

未知/重复字段、类型不符、越界、错误枚举及格式错误会拒绝整次导入。导入只更新预览，“写入改动”才执行冲突检查、写入与回读验证。导出的完整 g_foc.cfg 模板可直接交给配套 MCU 生成器；上位机也支持部分字段导入。

程序不再自带型号文件：预设改由运行时从外部导入（加载固件包时自动使用 AXF 同目录的 `parameters/`，或在变量管理器里手动选择/拖入 JSON）。不完整的历史档案已移除。

参数配置中的“选择预设目录”直接选择文件夹. 整套预设和机械、硬件、软件三组选择器按实际子目录显示分级菜单, 例如 `NEO/NEO_45H.json` 和 `V25/V25_60H.json`, 不根据文件名前缀分类. 根目录中的 JSON 直接列出, 旧的平铺目录仍可使用. 默认参数查找会递归搜索子目录, 子目录内的型号文件名应保持唯一.

配套固件选择 SAVED_FIRST 时，会在配置改变稳定后默认等待 3 秒，自动保存并重启：调试模式存 NOINIT，非调试模式存 Flash；RAM 写入可能触发持久化。FOC 配置写入要求 DISABLE 或 FAULT。


JSON 参数页只显示配置输入，按结构体和数组显示为可折叠树，支持展开全部、折叠全部和搜索自动展开匹配分支。旧 JSON 中标记为 role: derived 的字段仍可保留和保存，但不在参数页显示、搜索或作为配置写入 MCU。运行时计算结果通过变量监视器查看。

默认模板中的参数是配置输入，0 表示自动计算的参数仍可编辑。力矩环的 PID/积分上下限仍支持用户覆盖，0 明确标注“自动”；电流环 kp/ki 在 current_loop_bandwidth=0 时有效，保留手动配置。类型列仍放在最后。


cfg 保存配置输入；运行计算、校准覆盖和临时模式切换只修改 lo。采样频率、观测器电机引用、ADC 电流换算、PWM 周期计数以及 HFI 告警状态已移出配置模板。PID/ADRC 生效值位于 g_foc.lo.<控制器>.lo.effective，reference_change_max 位于 lo。参数页只读写配置，运行时生效值在变量监视器中查看。需要配套的新固件和 AXF（配置 Flash 版本 0x0C、NOINIT 自动布局指纹）。


首版配置参数按 JSON 中配置输入的顺序从 1 连续分配 id，revision 从 1 开始。应用有 ID 的 JSON 时，使用配套 param_list_manifest.json 严格核对 id、path、type、revision，再核对 AXF 的类型、偏移和位域；未知、已删除或不匹配的参数会拒绝整次导入，不会把旧 ID 映射为其他字段。manifest 随固件构建的 parameters 目录发布，放在程序旁或选择配套预设目录。无 ID 的部分配置仍按路径匹配。离线打开、编辑、保存不需要 manifest 或设备。

Flash 启动迁移缺项采用新固件默认值；JSON 部分导入则保留设备未提供字段的原值。固件只读取当前 0x0C Flash 配置，不迁移发布前的旧格式，NOINIT 调试快照不承诺跨固件保留。

参数文件配套: 加载固件包内的 AXF 时, 变量重写窗口优先使用 AXF 同目录的 `parameters/param_list.json` 和 `param_list_manifest.json`. 手动选择型号目录不会替换这套布局定义. 同目录中的 schema 或 manifest 更新后自动清除缓存, 带参数 ID 的型号预设必须与当前清单的路径、类型和版本一致. 若固件包缺少清单, 会报错而不会回退到程序附带的旧版本.

J-Link 参数读写按兼容性校验：设备参数描述块的格式版本、参数模式版本、配置大小、布局指纹、字段数量，以及配置和 FOC 状态地址必须与 AXF 一致。编译时间、固件版本、默认配置摘要和程序代码字节允许不同，因此布局和地址兼容的不同构建可配置参数。描述块仍从 AXF 指定的 Flash 地址读取；若重新链接导致描述块或 RAM 地址移动，需要加载设备对应的 AXF。写入前仍检查连接未变化及 FOC 处于 DISABLE/FAULT。


## 电机控制

“工具 → 电机控制”支持 Npcap、内核 PDO 和 J-Link，左侧为变量监视器，右侧为控制与仪表盘。J-Link 可以从 CM7 ELF/AXF 选择控制模式、控制字、状态字、目标和反馈变量，并提供 FocDriver 预设。连接不使能，不恢复上次运动指令。使用方法见 [电机控制页面](docs/motor_control.md)。

Windows 默认以普通权限启动，设备访问明确被拒绝时才提供保存并提权重启的入口。


### 设备固件与 AXF/ELF 匹配

支持构建标识的固件会发布当前运行镜像的身份. AvA Tool 加载 AXF/ELF 时校验文件摘要, 再在访问设备变量前核对设备身份. 符号和摘要从同一份文件快照解析, 后台编译替换文件不会使两者来自不同版本.

- 已匹配: 正常读取, 写入和采样.
- 明确不匹配: 变量窗口及连接/断开按钮的悬浮提示显示原因, 默认暂停变量读写, 位字段写入和采样. 在变量窗口点击 "强制使用 AXF/ELF" 可按已加载文件中的地址继续访问; 界面保留不匹配提示, 可随时点击 "取消强制使用". 连接, 复位, 烧录及原始 Flash 读取仍可使用.
- 未校验: 固件或 AXF/ELF 没有构建标识时显示提示, 继续支持旧固件调试. 未校验状态不代表已确认兼容.
- 校验信息暂时不可用: 已识别为支持校验的设备在本次连接中丢失身份时暂停访问, 等待启动完成或重新连接.

连续读取与高速采样最多每 100 毫秒重新核对一次, 写入前逐次复核. 强制使用只对当前连接, 已加载文件及设备本次启动有效, 不保存到会话. 断开重连, 重新加载或移除文件, 设备重启或固件身份变化, 校验信息暂时不可用时都会取消. 切换强制状态也会使排队的旧请求失效, 并停止旧高速采样; 后续请求按新状态执行. 参数编辑器仍检查参数布局, 地址及写入时的 DISABLE/FAULT 状态.

切换 AXF/ELF 时会使排队的旧地址请求失效, 监视通道更新地址后才恢复访问. 保留内存采样和 MIDI 发波在地址来源变化后需要重新开始. 多个变量窗口共用一个 J-Link 目标, 强制使用作用于该目标当前已加载的所有文件. 地址可能与设备实际布局不同, 应以当前文件中的符号地址为准核对读写内容.

界面会在所选固件包附近的 `archive` 目录查找相同构建标识的历史 AXF. 找到后显示 "加载匹配的 AXF" 按钮, 由用户选择加载. 归档清单需包含 `firmware_build.build_id`.

使用 `python tests/run_firmware_match_test.py` 运行不连接硬件的匹配, 强制使用, 自动取消, 旧固件兼容和摘要算法测试. 该测试需要支持 C++20 的宿主 g++.

### 共用 module

`ckit/include`、`ckit/src` 和 `ckit/include/ckit.h` 与 FocDriver 共用。桌面构建使用独立的 Makefile 设置，保留 `sim_stream.hpp`、依赖库和桌面工具；依赖中断及固件配置生成文件的运行循环不参与桌面库构建。修改共用头文件时，构建系统会重新编译依赖它的模块和应用代码。

参数 JSON 和 CSV 仍由应用解析文本、字段名称、枚举选项和取值范围。具有参数编号且受共用模块支持的字段，通过 `paramlist` 编码和解码，复用固件的记录格式、类型版本检查、位域处理及部分参数更新规则。字段位置来自当前 AXF 及其配套清单，不使用电脑端结构体的位置。无编号的旧文件、字符串以及模块尚不支持的整数宽度继续使用通用变量编辑器。导入失败不会提交部分修改。

Flash 数组的半精度浮点转换使用 module 的实现。仿真帧通过 module 的队列预读接口确认完整长度后再消费，支持旧版帧、分段到达和队列回绕。波形、频谱、日志、共享内存和队列使用当前 module 接口。

从固件目录更新共用源码：

```powershell
python scripts/sync_ckit.py D:/GitSpace/FSA/neofsa/CM7/FocDriver/ckit
```

在命令末尾添加 `--check` 可检查差异而不修改文件。同步保留桌面 Makefile 和仅在 ava_tool 中存在的文件。运行 `python tests/run_module_reuse_test.py` 可验证参数记录兼容性、错误输入不改变配置、全部半精度位模式，以及 C 与 C++ 的内存池布局、异步日志和仿真帧读取。

## 库依赖

J-Link 的 DLL、LIB、SO、DYLIB 统一放在 `ckit/lib/jlink/`，FFTW 库放在 `ckit/lib/fftw/`，两者均不再按操作系统划分子目录。构建与动态加载路径同步使用该布局。

Windows、Linux、macOS、Android 的平台实现统一位于 `src/platform/{win,linux,mac,android}`，构建统一使用 `python scripts/build.py <平台>`。安卓入口复用现有 ELF/DWARF 核心，APK 位于 `bin/android/ava_tool.apk`；当前是 J-Link/SWD 和变量监控首版，尚未通过真机 OTG 验证。环境配置、范围与验收步骤见 [多平台构建](docs/platforms.md)。

程序仅链接 `ckit/lib/ckit` 下的通用工具库, 不编译或链接电机控制库. 固件变量和安全状态通过 DWARF 与用户选择的诊断 JSON 解析. 公共接口在 `ckit/include`, 上位机短类型别名集中在 `src/ckit.h`. `scripts/sync_ckit.py` 同步工具库源码, 保留桌面 Makefile 和扩展; `scripts/sync_safety.py` 只同步安全诊断的通用 C 引擎.
