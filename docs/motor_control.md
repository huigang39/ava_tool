# 电机控制页面

从 **工具 → 电机控制** 打开。左侧直接嵌入程序现有的变量监视器，复用示波器、工具栏、缩放、图例、通道表及 FFT，显示位置、速度、电流、转矩及温度／电压曲线，并叠加已下发目标。温度和电压示波器默认收起，可点击“显示示波器”展开。右侧按“控制 / 连接 / 仪表 / 诊断”分页：控制页保留模式、特殊指令、目标和使能，连接页承载通信与 J-Link 映射，仪表页显示各表盘，诊断页收纳故障、PID 和日志。左右分隔线可拖动调宽，两侧独立滚动。仪表盘包含可拖拽的位置盘，以及速度、电流、电磁转矩、负载转矩、母线电压、逆变器／绕组／MCU 温度仪表。页面和确认弹窗使用程序默认样式。

示波器默认隐藏右侧统计表，可勾选“显示表格”展开；“显示曲线”勾选框控制该 Scope 的曲线显示。已有会话保留保存的显示设置。Y 轴可滚轮缩放、拖动平移，双击恢复自动适配，不再单独显示“自动 Y”按钮。Monitor 顶部的“同步测量”默认关闭；开启后，悬停任意时域 Scope 会在同一 Monitor 的所有可见时域 Scope 显示共同时间的竖线和各自曲线数值。频域图独立显示频率，不参与时间同步。鼠标进入波形区时显示竖直游标，在旁边集中显示同一时刻所有可见曲线的名称及数值，并按曲线颜色标记交点。折线按相邻有效采样点插值，阶梯曲线取保持值；数据断点或超出该曲线采样范围显示“—”。数值包含增益、偏置和显示单位；频域按共同频率显示幅值。在 Monitor 顶部“同步测量”右侧勾选“测量时间”后，同一 Monitor 的时域 Scope 共用一组 A/B 游标，可分别在不同 Scope 点击 A、B 两点，显示两点的绝对时间差（秒及毫秒），并可在任意 Scope 拖动游标调整；靠近采样点时自动吸附其时间。工具栏“测量时间”右侧的“清除”会清除整组测量点，取消勾选会关闭整组测量；不同 Monitor 之间保持独立，频域图不参与。跨 Scope 时间测量无需开启“同步测量”。开始选点后固定当前时间窗口，采样继续运行；测量期间用鼠标中键平移，取消勾选后恢复普通鼠标操作。

SDK 的 `torque` 为负载转矩，`electromagnetic_torque` 为电磁转矩，单位均为 Nm；目标输入、确认弹窗、仪表盘和波形纵轴使用相同单位，不对数值额外缩放。逆变器／绕组温度分别来自 `drive_temperature`／`motor_temperature`。SDK 尚未提供 MCU 温度；无有效反馈时显示“—”。仪表刻度只是显示量程，不代表电机限值。

每个仪表下方的“量程…”可设置上下限，应用后保存到会话，支持恢复默认。上下限必须为有限数值且下限小于上限；旧会话或无效设置使用默认量程。位置盘每圈对应所设量程的跨度，刻度使用 rad，并保留跨圈连续拖拽。改量程本身不发送控制命令，也不改变固件限值。

Windows 默认使用 EXE 内置运行库，无需指定 DLL；“高级运行库设置”保留自定义 DLL。旧会话中的 DLL 路径不会覆盖内置默认值。

## J-Link 变量控制（FocDriver）

1. 在变量管理器加载与目标上 CM7 程序匹配的 ELF/AXF，在顶部连接 J-Link。
2. 电机控制的通信后端选择 **J-Link**，点击“刷新变量”并选择 ELF 来源，再点击“FocDriver 预设”。各映射下拉框可搜索、更换变量，悬停可查看地址和宽度；目标、反馈及控制权字段在折叠项内。
3. 确保电机失能、退出校准，固件的 `g_cia402.cfg.enable=1`、`g_auto_ctrl.cfg.enable=0` 且生效配置已初始化，再点击“连接（不使能）”。模式选择、目标回车和使能仍沿用页面的确认弹窗。

预设的模式入口是 `g_cia402.in.mode_of_op`，使能/失能入口是 `g_cia402.in.ctrl_word.val`，状态反馈是 `g_cia402.out.status_word.val`，特殊指令是 `g_cia402.in.special_cmd`。这些变量采用 FocDriver 的 CiA402 编码；**不能换成内部 `g_foc.lo.mode/state` 直接写入**，它们需要固件函数维护控制标志和状态转换。自定义映射应保留相同协议语义，不是任意枚举值的转换器。

连接会把 `g_comm_shm.cfg.enable` 写为 0，避免 CM4 共享内存覆盖 J-Link 命令。断开时请求并等待失能，但保持共享内存输入关闭，避免恢复残留的使能命令。切回 EtherCAT 前先关闭上位机的旧指令，再复位固件恢复共享内存。这里不修改固件源码，不写 Flash，也不自动安装驱动。

切入 CSP、CSPC、PP、PPC、PD 时先写入当前位置并清零其余目标，等待模式反馈，再把固件锁存的位置同步到输入框与目标指针；保持原使能状态。PP/PPC 显式目标通过新设定点握手提交。方向和速度单位取生效配置，界面统一转换到 rad、rad/s、A、Nm，显示单位切换继续可用。波形、仪表平均值和全局点数统计复用原有监视器。

变量地址和类型每次连接从当前 ELF 重新解析，会话只保存来源和变量名。未解析、宽度/类型错误、重叠映射拒绝连接；探针重连或复位后，旧连接的写入会被拒绝，必须重新连接。单个映射支持一个执行器。J-Link 约每 20 ms 轮询，位置插补和 Npcap PID 面板不在此后端提供；USB 断开、程序崩溃时没有目标端通信看门狗，不能保证失能命令送达。

## Npcap 用户态连接

页面提供“EtherCAT · Npcap”、“EtherCAT · 内核 PDO”和“J-Link”，首次打开及新建会话默认选择 Npcap。已有硬件会话保留原选择；旧模拟器会话迁移为 Npcap，并清空原模拟设备路径。默认选择不会自动连接或使能。

选择“EtherCAT · Npcap”，点击“扫描网卡”，明确选择连接执行器的有线网卡，再点击“连接（不使能）”。不需要 ava_eth 内核控制设备，但需要 Npcap 驱动。未安装或无法加载时，页面弹窗提供“打开官网下载页”（https://npcap.com/#download）和重新检测；不会自动下载或安装驱动。安装后重新检测、扫描即可。

连接初始化的寄存器事务使用独立的 100 ms 等待预算，等待期间可发送一次只读 DL 状态探测帧，促使 Npcap 交付待接收数据。无副作用的状态／标识读取最多重试两次，每次使用新报文索引；邮箱数据读取、写操作和 PDO 不重放。探测回包不能替代原请求的确认。初始化结束即恢复运行期策略，循环 PDO 的 5/20 ms 超时与看门狗不变。超时信息包含寄存器地址、连接／运行阶段及读取重试次数。

扫描列表显示 Windows 网卡友好名称，支持中文，名称以 UTF-8 保存到会话；实际连接仍使用对应 Npcap 设备路径。同名网卡按独立路径区分，悬停可查看设备描述和路径；“设备路径”展开后可手动编辑。无法匹配 Windows 名称时保留原路径作为回退显示。

当前 Npcap SDK 支持单轴，复用内核 PDO 协议状态机、CiA402 使能反馈、位置插补和命令看门狗；周期收发由 SDK 内部线程完成，界面只提交命令和读取快照。超时或错误会撤销有效反馈、停止周期并尝试零输出／SAFEOP；停止后需明确重新连接。用户态调度不保证硬实时。勿让其他主站同时控制同一网卡上的执行器。

实现同时位于相邻 `ava_eth` 项目的 `sdk/c/src/user_hardware.cpp` 和 C ABI；修改后构建 SDK，再运行同步脚本并重新构建 ava_tool。自动测试使用模拟 ESC 传输，未验证真实 Npcap 网卡带电机运行。

## 操作流程

1. 选择 Npcap 并扫描、选择网卡，或选择内核 PDO 并扫描、选择控制设备，点击“连接（不使能）”。
2. 选择执行器、控制模式，例如 `-9 CSVC`，在弹窗中确认设置模式。填写参考速度 `1 rad/s`，回车后确认下发目标。
3. 点击“使能”并确认，观察反馈与波形。
4. 修改目标后回车、确认即可更新；“失能”立即请求停止选定执行器输出，断开连接会调用 SDK stop 并关闭控制会话。

目标输入在回车前只修改草稿；回车或选择新模式会打开原生确认弹窗，取消不会下发。曲线中的目标表示 SDK 已接受的目标。确认切换模式时保持原有使能状态，无需再次点击使能；原本失能的执行器也不会因此使能。Npcap 在同一次加锁更新中切换模式、初始目标和插补参数，不插入失能控制字。内核或旧 SDK 使用先失能、设置新模式、再恢复原使能状态的兼容流程。

切入 CSP、CSPC、PP、PPC、PD 时，使用执行切换时的最新反馈位置作为第一条位置目标，同时清零速度／电流／转矩目标；位置仪表盘目标指针和输入框同步到运行库实际接受的初始位置，不使用弹窗打开时的旧位置。控制区只保留一个随状态切换的“使能／失能”按钮，没有“发送指令”按钮。它与“连接／断开连接”按钮均为 170×30，连接和使能为绿色，断开和失能为红色。位置盘在失能时拖拽只暂存目标；已使能且处于位置模式时，拖拽继续实时更新目标。

明确点击下拉框中的模式（包括重新点选当前项）都会弹窗确认并重新初始化目标位置。确认弹窗中的位置预览随反馈更新，执行时仍以 SDK 最新原始多圈反馈为准。切换成功后统一更新目标输入框与指针，并重置输入控件的旧编辑缓存；仪表数字的平均显示不参与控制目标计算。

默认已显示 CSP 并不代表已经向设备提交了模式。连接后的首帧有效反馈会初始化位置目标显示；如果直接点击使能进入 CSP、CSPC、PP、PPC、PD，且尚未通过模式切换或目标下发初始化该模式，则执行使能前重新采样当前位置，并清零速度、电流、转矩附加目标。输入框与指针同步到这次接受的位置。已在确认弹窗明确提交的位置目标会保留。日志分别标明“位置模式首次使能”“使能已确认”“目标指令已确认”和“模式请求已处理”。

Npcap 在线切换还会等待从站的实际模式与目标模式一致，且该请求的 PDO 已确认、反馈有效、使能保持。200 ms 内未满足则停止通信，错误记录请求／反馈模式、目标／反馈位置与状态字。失能时仅暂存模式，不要求从站回读新模式。页面在模式选择框旁显示“实际反馈模式”，模式切换记录保留切换前位置和速度以及接受的初始位置。读回 CSP 只确认协议状态，不证明物理电机已停止或位置环参数正确。

## 连接执行器

“特殊指令 · special_cmd”对应 FocDriver `app/include/cia402.h`，通过 PDO 对象 `0x2080` 写入：0 无、1 失能、2 使能、3 校准、4 无感、5 出轴角度传感器标零、6 清错、7 扭矩传感器标零。选择后弹窗确认，收到 PDO 回包后显示已下发的值；回包确认不表示校准或标零成功，具体结果需查看反馈与固件故障页。

特殊指令非零时固件不处理普通控制字。重复执行一次性指令前先选“无”；恢复普通控制前也先选“无”，程序保持失能。校准、无感、标零和清错要求先失能；校准可能运动，并受界面心跳和 SDK 看门狗保护。“失能”、断开或看门狗超时会取消使能／校准特殊指令。特殊指令不保存到会话、不在重连后自动重放。

内置 Npcap 后端已支持此接口。内核 PDO 需要带 `AVA_ETH_CAP_SPECIAL_CMD` 能力的新驱动；旧驱动下下拉框会禁用并提示，不自动安装驱动。

Windows 上安装 ava_eth 网络驱动和控制设备驱动后，启动 `bin/win/ava_tool.exe`。程序默认以启动者的权限运行，不在启动时申请管理员权限。扫描或连接设备先按当前权限尝试；驱动明确返回访问被拒绝时，才提示“保存并重启”，确认后申请 Windows UAC。Npcap 允许普通用户访问时，无需提权。

后端选择“EtherCAT · 内核 PDO”。可以扫描控制设备并选择路径，也可留空使用 SDK 找到的首个设备。这里选择的是设备管理器中的控制设备，不是 Npcap 网卡名称；网络驱动绑定的网卡由 ava_eth 驱动配置决定。

实机页面默认使用 20 ms 接收预算；取消复选框可恢复 SDK 的严格 5 ms 预算。旧版会话的默认预算迁移为 20 ms；之后手动选择并保存的 5 ms 设置会保留。请确认“20 ms 接收预算”已勾选。界面轮询 50 Hz，EtherCAT 周期由所选通信后端执行。当前硬件 SDK 支持一个执行器。连接完成仍保持不使能，确认目标后点击使能按钮并确认页面显示的真实电机目标。

位置单位 rad，速度 rad/s，电流 A，转矩 Nm。所有控制模式编号沿用 ava_eth。回零触发、I/F、V/F、ASC 专用参数尚未通过当前 SDK 提供，页面不会伪造对应功能。温度没有有效标志时显示“—”。

## PD / PID 参数

通过 Npcap 连接后，右侧展开“PD / PID 参数”，勾选需要修改的参数并填写值，再点击“写入所选参数”，在原生 ImGui 弹窗核对并确认。支持运行中在线修改，保持当前使能状态、控制模式和运动指令，不需要断开或重新使能。当前支持单执行器网段；不保存到 Flash，也不随会话恢复自动写入。未勾选的参数保持不变。

| 参数 | CM4 对象（子索引 0） | 编码 |
| --- | --- | --- |
| PD Kp / Kd | 0x2400 / 0x2402 | IEEE float16 |
| 位置→转矩 Kp | 0x2404 | float32 |
| 速度→转矩 Kp / Ki | 0x2408 / 0x240C | float32 |
| 位置→电流 Kp | 0x2410 | float32 |
| 速度→电流 Kp / Ki | 0x2414 / 0x2418 | float32 |

以上是 CM4 当前公开的全部 8 项增益，没有独立位置 Ki/Kd 或电流内环 PI 对象。CM7 的 `comm_shm_neo_sync_pid_param` 按当前转矩／电流控制路径选择对应位置 P、速度 PI；PD 增益独立处理。参数必须有限且非负，PD 最大 65504。“上次发送”显示编码后的发送值（包括 float16 量化），不是设备测量值。

SDK 在连接初始化时，将当前未使用的原始位置字段和转矩前馈字段预留为固定宽度的参数槽；运动字段偏移和 RxPDO 总长度保持不变。运行中先在填充槽暂存数值，再通过包含 SI0 的 Complete Access 写入 0x1600，将对应槽映射为所选增益，发送后恢复为填充槽。SI0、字段宽度和低 WORD 始终不变，仅切换对象索引的高 WORD，避免 CM4 中断交错时改变运动字段。所选参数逐项生效，并非整批同时切换。

`ava_eth_set_pid` 异步排队，`ava_eth_get_pid_status` 查询完成状态。同一个通信线程处理 PDO 与 CoE，等待邮箱期间继续收发 PDO；上位机持续续约看门狗。运行中不切换 EtherCAT 状态、不失能或重新使能。普通输入错误在发送前拒绝；通信失败沿用停机路径，紧急失能帧保留可能仍映射的参数值，避免误将增益写零，之后在 PREOP 恢复正常映射。

**现有固件限制：** CM4 源码保持不变。PID 的 `ecat_coe_read/write` 是空实现，且这 8 项参数只有 RxPDO 映射权限，因此不能回读当前值。此实现不调用 PID 标量 SDO，不提供“读取参数”，也不把协议确认称作参数回读校验；WKC、AL 状态仅确认通信及控制状态。SDO 仅用于已有正常实现的映射对象。失败后可能已有部分参数写入，不自动重试或回滚。下次连接识别到已知的 PID 映射时先恢复正常映射，不重发增益。

`python tests/run_motor_pid_mapping_test.py D:/GitSpace/FSA/neofsa` 将未修改的 CM4 映射代码与 SDK 生成的 PDO 数据一起编译运行，验证共享内存地址、编码、未选项保留，以及逐 WORD 更新映射时使能、模式和运动指令不变。只写入上位机 build 目录，不编译或修改固件。SDK 测试另覆盖在线更新、慢邮箱、看门狗、异常停机与参数保留；上位机测试覆盖异步提交与原生确认窗口。这些主机测试不替代实机验证。

NEO 固件通过 PDO `0x2008`（`get_pvct.t`）上报出轴负载转矩，通过 `0x200A`（`get_pvct.te`）上报电磁转矩。SDK 的既有 `torque` 字段保持负载转矩语义，新增 `electromagnetic_torque` 使用原保留槽，结构大小及 ABI 1 不变；对应有效位为 `AVA_ETH_ELECTROMAGNETIC_TORQUE_VALID`。两个仪表分别显示，转矩波形同时包含负载转矩、电磁转矩和目标；仪表沿用 200 ms 平均，波形保留原始采样。旧 SDK／旧内核驱动没有电磁转矩有效位时显示“—”，不能将其保留槽的零值视作测量值。内置 Npcap 已接入两路，固件无需为此修改；内核后端需使用更新后的驱动才能新增电磁转矩反馈。

## 反馈和生命周期

右侧"故障与警告详情"按 FocDriver 的通信位图逐位显示中文说明,并保留 Error 页号,PDO 对象地址,原始十六进制值及位号;悬停说明可查看固件字段名.新出现错误时自动展开,变化也会写入操作记录.Error3 单独标为警告,Error4 标为校准详情;Error5..8 或未定义位保留原始值,不猜测含义.反馈失效时会标注为最后接收的数据.

定义由 FocDriver 的 `tools/safety/safety_generate.py` 从当前 `safety/safety.h`,`shared_memory_comm.h`,`shared_memory_comm.c` 和 `drv8353.h` 生成.Error2 已退役,非零按未知位处理;通信 Error4 与内部校准页有不同的位排列.Error1 bit19 是参数/配置/上电自检汇总位,需进一步查看 `g_mc.lo.safety` 的内部故障页及原因.控制器 `0x80000008` 只代表 CiA402 故障,不能当成固件位图解码.点击实时故障条目可打开对应错误码快照和排查详情.

"工具 → 功能安全"按用户选择的 JSON 读取诊断对象和解释规则. 在"配置"中选择自己的配置目录和文件,共享错误页按 JSON 的协议条件选择. "系统变量"使用当前 AXF/ELF 的 DWARF 展开成员和数组; 也可在 JSON 中指定其他子系统路径. 指针值和目标字段由后台读取, 不硬编码成员地址.

"单值或离线解析"使用同一份 JSON, 支持布尔,8/16/32/64 位整数,枚举以及 f32/f64. 故障位按掩码拆分, 枚举按完整值匹配, 普通计数和物理量保留数值; 未知含义明确标记, 不把非零一律当故障. 变量绑定只读, 缺失,断连和过期数据单独显示. 整组采样不是固件侧原子快照, 具体配置与使用见 [Safety 诊断](safety.md).

JSON 由用户保存在自己的目录,程序不内置或复制,可通过"打开 JSON"和"加载 / 重载"更换. 旧解析器 ID 通过 `aliases` 兼容已有会话, 新配置采用模块内的 `safety` 名称. 更新 FocDriver 后按需同步通用 C 核心及原电机面板的通信位图表:

```powershell
python scripts/sync_safety.py D:/GitSpace/neofsa/CM7/FocDriver
python scripts/sync_motor_faults.py D:/GitSpace/neofsa/CM7/FocDriver
make -j4
```

实时反馈包含位置、速度、电流、力矩、母线电压、模式、温度、错误码及请求序号。通信诊断包含 WKC、AL 状态、发送/接收、超时、错过周期、最大回包耗时和固件原始错误页。错过周期表示未赶上计划时刻，不能直接当作丢包。

界面每帧向后台更新存活时间；后台每 50 ms 只为该页面明确使能的轴续期。超过 200 ms 没有界面心跳时停止续期并请求 stop；驱动命令看门狗为 250..1000 ms。故障、反馈失效或请求失败也撤销续期，错误显示在页面和操作记录中。

关闭页面、加载会话、新建会话和退出应用都会断开控制会话。会话只保存页面开关和连接配置，不恢复连接、运动目标或使能。故障复位只执行一次，不自动重新使能。

失能和断开都是软件请求，链路断开时无法确认机械停机。复位和停止的实际效果取决于 SDK、驱动和执行器固件。

## 圆形位置控制盘

仪表盘的反馈数字与反馈指针使用最近 200 ms 的有效采样平均值，按 SDK 采样时间取窗口，重复绘制不会改变权重。位置先对完整多圈值平均，再分解为圈数和单圈角度，避免越过 ±π 时跳到错误角度。模式切换、执行器切换和重新连接不混入旧窗口；反馈失效立即保留无效状态。目标指针、控制指令、故障判断和变量监视器原始波形不使用这项平均。

默认位置量程为 −π～π rad（度制为 −180～180 deg）。旧会话的默认 0～2π 量程会迁移，其他自定义量程保留。位置卡片的单位下拉框支持 rad/deg，速度卡片支持 rad/s、deg/s、rpm；目标输入、确认弹窗、量程编辑和波形显示同步换算，SDK 内部仍使用 rad 和 rad/s。单位选择随会话保存，切换单位不发送指令。切换时波形从保留的原始历史重新换算，避免一条曲线混用单位。

位置读数分解为“有符号圈数 + 单圈角度”，单圈角度在 [−π, π)；两者相加等于固件多圈反馈，例如 2π+0.2 rad 显示 1 圈 + 0.2 rad。另显示完整多圈位置和目标圈数。圈数直接依据固件多圈位置，不对采样速度积分，不在无效反馈期间虚增；掉线显示最后位置。固件清零/重启后的圈数以其新反馈为准。

在右侧控制栏选择位置模式（例如 8 CSP 或 -8 CSPC），拖拽蓝色指针或末端圆点即可设定位置。绿色指针显示实际反馈。正向为逆时针，拖拽跨过 0/360° 时连续累加，可设定多圈位置；旁边保留 rad 和角度读数。

未使能时，拖拽只修改编辑值，需要明确应用／使能。轴已使能、反馈有效且实际模式匹配时，拖拽会以最多 20 Hz 更新位置目标并发送最终位置；不会自动使能或切换模式。停止、失能、切换轴、切换模式、关闭页面或断开会取消未发送的拖拽请求。实机动作仍通过 ava_eth SDK 执行。

### 位置插补

右侧“位置插补设置”默认启用位置插补，适用于 `8 CSP` / `-8 CSPC`。失能时设置最大速度（默认 1 rad/s）和最大加速度（默认 2 rad/s²），再手动应用目标并使能。目标输入框和指针共用此轨迹设置。其他控制模式仍使用原目标发送方式。

蓝色指针表示最终位置，绿色指针表示反馈位置。周期层生成加速、匀速、减速的位置指令；移动中更改目标保持轨迹位置和速度连续，反向或目标进入制动距离时先减速，可能越过新目标后再返回。此版本为梯形轨迹，不限制加加速度，不是 S 曲线。

硬件在 CiA402 使能完成后每次 PDO 推进一步，通信延迟不追赶漏掉的步骤，因此实际运动时间可能延长。失能、停止、故障、租约过期均取消轨迹；重新使能从反馈位置重新规划。参数限制针对指令轨迹，实际机械运动取决于驱动调节及负载。

需同步更新 ava_eth SDK DLL 和内核驱动。新版通过 `AVA_ETH_CAP_INTERPOLATION` 能力位检测支持情况；旧驱动启用插补时会报更新提示，不会悄悄退回阶跃位置控制。会话不自动恢复轨迹或使能。
